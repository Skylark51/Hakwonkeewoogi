# 학원키우기 게임 설계

## 게임 방향

학원키우기는 그래픽 배치형 타이쿤보다 **Football Manager에 가까운 데이터 중심 경영 시뮬레이션**을 목표로 한다.

핵심은 단순히 돈을 벌어 건물을 확장하는 것이 아니라 다음 선택 사이의 충돌이다.

- 성적 vs 학생 컨디션
- 우수 학생 선발 vs 빠른 규모 확장
- 좋은 강사 vs 고정 인건비
- 시설 투자 vs 현금 보유
- 주력 과목 집중 vs 다과목 확장
- 단기 평판 vs 장기 육성

---

## 1. Intro / New Game

게임 시작 전에 짧은 서사를 제공한다.

인트로는 게임 내부 편집기로 수정할 수 있게 하여 개발자가 C++ 코드를 직접 편집하지 않아도 된다.

새 게임에서 결정:

- 학원명
- 주력 과목
- 향후 지역 선택
- 향후 난이도/초기자금 선택

현재 v0.2에서는 학원명과 주력 과목을 구현한다.

---

## 2. 학생 유입과 상담

학생은 자동으로 학원에 등록되지 않는다.

```text
상담 문의
→ 학생 프로필 확인
→ 상담
→ 등록 / 거절
→ 반 배치
→ 주간 성장
```

학생의 성적만으로 판단하지 않도록 다양한 능력치를 둔다.

### 학생 능력치

학업:
- 현재 성적
- 잠재력
- 이해력
- 암기력
- 집중력
- 시험 적응력

태도:
- 성실성
- 출석률

상태:
- 스트레스
- 피로
- 만족도

외부 요인:
- 학부모 요구 수준
- 상담 적합도
- 월 수강료
- 향후 가정환경/친구관계/학교생활

### 향후 추가

- 국영수과 개별 성적
- 내신/수능 성향
- 학습 유형
- 성격
- 학생 간 관계
- 친구 추천 등록
- 퇴원/전원
- 문제 학생
- 장학생

---

## 3. 학원의 주력 과목

초기에는 한 과목을 주력으로 정한다.

효과:
- 해당 과목 상담 유입 증가
- 원장 직강 효율 증가
- 학원 브랜드 형성

향후:
- 단과 전문학원
- 종합학원
- 입시 전문
- 내신 전문
- 최상위권 전문
- 관리형 학원

으로 성장 방향을 분기한다.

---

## 4. 강사

게임 시작 시 강사는 원장뿐이다.

강사를 채용하면서 과목 범위를 확장한다.

### 강사 능력치

- 강의력
- 상담
- 학생 관리
- 스타성
- 체력
- 담당 과목
- 급여
- 계약금

### 캐릭터 특성

와라! 편의점처럼 능력치뿐 아니라 사람이 기억되는 특성을 둔다.

예:
- 스타강사형
- 엄격한 관리형
- 친근한 상담형
- 연구·교재형
- 체력 좋은 열정형
- 무난한 균형형

향후:
- 지각 잦음
- 학생 인기가 높음
- 학부모 상담에 강함
- 상위권 전문
- 하위권 전문
- 이직 욕구가 높음
- 경쟁학원 출신
- 원장과 궁합이 나쁨

등의 장단점을 동시에 가진 trait system으로 확장한다.

---

## 5. 주간 트레이닝

기본 시간 단위는 **1주**다.

현재:
- 균형 운영
- 성적 집중
- 기초 강화
- 컨디션 관리

학생 성장은 다음 요소의 함수가 된다.

```text
학생 성장 =
강사 효과
+ 잠재력
+ 이해/암기
+ 성실/집중
+ 출석
- 스트레스
- 피로
+ 주간 방침
+ 변동 요소
```

향후 학생별 훈련을 추가한다.

예:
- 숙제량 증가
- 오답노트
- 일대일 보충
- 자습
- 모의고사
- 상담
- 휴식
- 특강
- 방학 집중반

---

## 6. 문제와 이벤트

규모가 커질수록 좋은 일만 생기지 않는다.

이벤트 발생 조건을 학원 상태와 연결한다.

### 학생
- 스트레스 과다
- 성적 정체
- 결석
- 학부모 민원
- 퇴원 위험
- 학생 간 갈등

### 강사
- 번아웃
- 급여 인상 요구
- 경쟁학원 스카우트
- 수업 평가 악화
- 스타강사 독립

### 시설
- 정원 초과
- 냉난방 문제
- 비품 교체
- 안전 문제

### 경영
- 현금 부족
- 임대료 상승
- 세금
- 지역 학생 수 변화

현재 v0.2에서는 조건 기반 주간 이벤트의 기초를 구현한다.

- 이름
- 주력 과목
- 평판
- 학생 수
- 주간 변동

향후:
- 동일 학생 상담 경쟁
- 광고 경쟁
- 강사 스카우트
- 시험 성적 비교
- 지역 점유율
- 가격 경쟁
- 경쟁학원 폐업/확장
- 신규 경쟁학원 등장

## 구현 원칙

- 실제 효과가 없는 메뉴는 만들지 않는다.
- 코드 구조를 보여주기 위한 더미 폴더를 만들지 않는다.
- 새 시스템은 기존 주간 루프와 연결한 뒤 추가한다.
- UI와 simulation core를 분리한다.
- 데이터 양이 커지는 시점에 SQLite로 이전한다.
